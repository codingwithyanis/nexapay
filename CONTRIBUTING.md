# Contribution

Chaque évolution doit respecter le cahier des charges NexaPay et conserver la priorité à l'intégrité financière.

Avant de proposer une modification :

- ajouter ou adapter les tests pertinents ;
- vérifier l'impact sur l'authentification, l'autorisation et l'audit ;
- prévoir une migration rétrocompatible lorsqu'un schéma évolue ;
- documenter toute décision structurante dans `docs/adr/` ;
- ne jamais inclure de secret, donnée carte ou PII inutile dans le code, les fixtures, les logs ou la documentation.
